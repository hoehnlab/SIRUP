Preparing FASTA with rrad for SIRUP

This guide prepares demultiplexed reads with the standalone rrad package, then passes an annotated FASTA file to SIRUP. Demultiplexing, layouts, whitelist discovery, and read reformatting are upstream steps. SIRUP begins with that file and performs IgBLAST annotation, filtering, clustering within barcodes, consensus generation, and IgBLAST annotation of the consensus sequences.

The examples are not evaluated during rendering: supply your own reads, output paths, and reference databases.

Install the preparation tool separately

install.packages("remotes")
remotes::install_github("indianewok/rrad@v1.2.1")

rrad is public and compiles its embedded RAD engine as part of R package installation. It does not require a separate RAD executable. SIRUP can process an existing prepared FASTA without installing rrad.

Small built-in resources are included in rrad. Large whitelists are downloaded by rrad when first requested, checked against their pinned size and SHA-256 digest, and cached for reuse. Prepare a machine for offline work with rrad::rad_download_whitelists(); see the rrad documentation for cache settings.

Demultiplex your reads

Choose a layout that matches the library; five_prime below is an example. For an assay with a different structure, pass your own CSV or seqspec file as described in Custom read layouts and whitelists.

demux <- rrad::rad_demux(
  layout = "five_prime",
  fastq = "reads.fq.gz",
  out_dir = "prepared",
  output = "sample"
)

demux$artifacts$fastq
demux$stats

The result identifies the exact output files and records the embedded engine used. Optional arguments include kit, global_whitelist, custom_whitelist, auto_whitelist, max_reads, chunk_size, and threads. Builds without OpenMP use one effective thread. Use ?rrad::rad_demux for supported settings and their defaults.

Write an IgBLAST-ready FASTA

prepared <- rrad::rad_reformat(
  demux,
  output_fastq = "prepared/sample-igblast.fasta",
  to_fasta = TRUE,
  header_format = "presto"
)

prepared$artifacts$fasta

Despite the argument name output_fastq, this writes FASTA when to_fasta = TRUE. The explicit destination keeps the demultiplexed FASTQ. The output has a whitespace-free identifier such as:

>read1|BARCODE=BC01|UMI=ACGT
ACGTACGT

BARCODE uses the nonempty spatial BC:Z tag when present, otherwise the corrected CB:Z tag. UMI comes from UB:Z; missing tags are omitted. Reads need a usable barcode for spatial clustering. SIRUP recognizes this canonical header form and the older read1|umi:ACGT|barcode:BC01 form.

Use header_format = "presto" explicitly: conversion to FASTA alone keeps SAM-style tags in the comment after whitespace, where IgBLAST does not retain them as part of the query identifier.

Begin SIRUP processing from FASTA

Configure IgBLAST, pRESTO, vsearch, and muscle before running this step. SIRUP runs IgBLAST through the airrblast package. Build the IgBLAST databases one time with airrblast::downloadIMGT() and airrblast::imgtToIgblast(). The database/ and fasta/ folders must be in igblast_base, or in the folder that you give as igblast_refs.

result <- SIRUP::processSpatialSample(
  input = "prepared/sample-igblast.fasta",
  output_dir = "processed",
  receptor = "ig",
  organism = "human",
  igblast_base = "/path/to/igblast",
  muscle_exec = "/path/to/muscle",
  imgt_dir = "/path/to/imgt",
  nproc = 8
)

result$db_pass

Ordinary FASTA input is detected automatically and receives the first IgBLAST pass. SIRUP then filters the AIRR calls, writes barcode-annotated spatial FASTA, groups reads within each barcode, builds consensus sequences, and runs a second IgBLAST pass before writing the final AIRR table. The first pass does not search a constant-region database, so it writes no c_call column.

input_type = "spatial_fasta" is only for FASTA already annotated, filtered, and prepared for consensus. It skips the first IgBLAST/filtering stage; do not select it merely because newly demultiplexed reads are in FASTA format. An existing AIRR table or TSV is another entry point after initial annotation.

Use receptor = "tr" with the matching TCR databases for a TCR run. Demultiplexing does not choose the IgBLAST receptor mode.

Visium HD preparation

For the supported Visium HD paired-barcode layout, select the appropriate layout and correct both barcode parts upstream. Confirm the layout matches the experiment on a pilot subset before a full run.

spatial_demux <- rrad::rad_demux(
  layout = "visium_hd",
  fastq = "spatial_reads.fq.gz",
  out_dir = "prepared",
  output = "spatial",
  joint_bc_mode = "strict"
)

coordinates <- rrad::rad_reformat(
  spatial_demux,
  output_fastq = "prepared/spatial-coordinate.fq.gz",
  coordinate = "vizHD-v1",
  bin_size = 2
)

rrad::rad_reformat(
  coordinates$artifacts$fastq,
  output_fastq = "prepared/spatial-igblast.fasta",
  to_fasta = TRUE,
  header_format = "presto"
)

Coordinate rewriting and pRESTO header formatting are separate calls. The second call places the coordinate-derived BC:Z value in BARCODE, for example s_002um_00001_00002-1. Pass this FASTA to processSpatialSample() as above. See Process reads into spatial AIRR tables for downstream spatial annotation and analysis.
