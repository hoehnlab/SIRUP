This vignette takes you from demultiplexed long reads to an AIRR table in which each consensus receptor sequence has a spatial ID. The next step, createSIRUP(), is in vignette("SIRUP", package = "SIRUP").

The pipeline calls external programs (IgBLAST, pRESTO, vsearch, and MUSCLE). A vignette cannot run these programs on every computer, so the chunks that call them show code only. The other chunks run on small samples of the MG thymus data that come with SIRUP.

The pipeline

Spatial AIRR-seq libraries are long-read sequencing libraries of receptor transcripts. Each read carries a spatial barcode, which identifies its spot. In most protocols it also carries a UMI, which identifies its original molecule. The processing has two parts:

  1. Demultiplexing, in the separate rrad package. rrad finds the barcode and UMI in each read, corrects them against the whitelist, and writes them into the read header.
  2. Consensus building, in SIRUP. processSpatialSample() runs these steps:
Step Tool What it does
1 IgBLAST (airrblast::assignGenes()) Annotates each read with V(D)J genes
2 filterAirr() Removes reads that are not receptors or are too short to use
3 pRESTO ClusterSets.py Groups the reads of each spot by sequence identity (vsearch)
4 pRESTO AlignSets.py Aligns the reads in each group (MUSCLE)
5 pRESTO BuildConsensus.py Builds one consensus sequence per group
6 airrblast::assignGenes() and addGaps() Annotates the consensus sequences, adds the IMGT gaps, and writes the AIRR table

Long-read sequencing has a high error rate. A consensus of several reads removes most random errors. The spot barcode stays in the sequence header through every step, so each consensus sequence keeps its spot.

Install the external tools

You need these programs on your computer or cluster:

  • IgBLAST (igblastn) from NCBI, with its internal_data and optional_file folders.
  • IMGT germline references, both as IgBLAST databases and as gapped FASTA files. The airrblast package downloads and converts them (see below).
  • pRESTO (pip install presto).
  • vsearch, which ClusterSets.py calls.
  • MUSCLE, which AlignSets.py calls. The SIRUP paper used MUSCLE 3.8.31.

The Immcantation Docker image contains most of them. If you use it, run R inside the container and install airrblast.

Make sure R can find the programs:

Sys.which(c(
  "ClusterSets.py", "ParseHeaders.py", "AlignSets.py", "BuildConsensus.py",
  "vsearch"
))
file.exists(file.path("~/share/igblast", "bin", "igblastn"))

An empty string means R cannot find that program. Add its folder to PATH, or give its full path to processSpatialSample() (muscle_exec). SIRUP runs IgBLAST through airrblast. It always uses <igblast_base>/bin/igblastn.

Build the IgBLAST databases

SIRUP installs the airrblast package. Use it one time to download the IMGT germlines and build the IgBLAST databases:

library(airrblast)
downloadIMGT("~/share/imgt", organism = "human")
imgtToIgblast("~/share/imgt", "~/share/igblast_refs", igblast = "~/share/igblast")

imgtToIgblast() writes the database/ and fasta/ folders into ~/share/igblast_refs. Give that folder to processSpatialSample() as igblast_refs. If you leave igblast_refs out, SIRUP looks for those folders in igblast_base. Give the IMGT folder as imgt_dir. airrblast supports human, mouse, and rhesus monkey.

Demultiplex with rrad

rrad is a separate package. Install it from GitHub:

remotes::install_github("indianewok/rrad")

rrad::rad_demux() finds and corrects the barcodes and UMIs. rrad::rad_reformat() then writes a FASTA file that IgBLAST can read. Choose the layout that matches your library:

demux <- rrad::rad_demux(
  layout = "five_prime",
  fastq = "reads.fq.gz",
  out_dir = "prepared",
  output = "sample"
)

rrad::rad_reformat(
  demux,
  output_fastq = "prepared/sample-igblast.fasta",
  to_fasta = TRUE,
  header_format = "presto"
)

Use header_format = "presto". It puts the barcode and UMI into the read identifier, which IgBLAST keeps:

>read1|BARCODE=AAACAAGTATCTCCCA|UMI=TCACATTCTGTA

parseRadSequenceIds() reads these tags into columns. processSpatialSample() calls it for you, but you can use it to check a file:

library(SIRUP)

headers <- data.frame(sequence_id = c(
  "read1|BARCODE=AAACAAGTATCTCCCA|UMI=TCACATTCTGTA",
  "read2|BARCODE=AAACACCAATAACTGC|UMI=AAAAAGGCTGGT"

parseRadSequenceIds(headers)

Run the consensus pipeline

processSpatialSample() runs every step from the table above. It prints each command before it runs it. If a command fails, it stops and shows the command.

You can start from three types of input:

input input_type First step that runs
FASTA or FASTQ from rrad "auto" or "raw_reads" IgBLAST on each read
AIRR table (path or data frame) from a first IgBLAST pass "auto" or "airr" filterAirr()
FASTA that is already filtered, with the spot in the header "spatial_fasta" pRESTO clustering

Use receptor = "tr" for TCRs. Run BCRs and TCRs as separate calls.

runIgblast() calls airrblast::assignGenes(), which does not search a constant-region database. A table made from raw reads has no c_call column.

With UMI support

Reads of one molecule can differ by sequencing errors. At identity = 1.0, those reads fall into different clusters, and each cluster can then fail the two-read minimum. With umi_support = TRUE, SIRUP first groups the reads of each spot and UMI at a looser identity (umi_identity, default 0.95). It builds one consensus per molecule from the productive reads only. The spot-level step then combines the molecules and sums their reads.

umi_support needs an AIRR table with umi and productive columns, so give it the output of the first IgBLAST pass. This is the call we used for the MG thymus BCRs in the SIRUP paper:

result <- processSpatialSample(
  input = igblast_reads,           # read-level AIRR data frame
  input_type = "airr",
  output_dir = "processed/kh02_bcr",
  receptor = "ig",
  identity = 1.0,
  consensus_freq = 0.51,
  cluster_field = "barcode",
  germline_glob = "~/share/germlines/imgt/human/vdj/imgt_human_IG*.fasta",
  igblast_base = "~/share/igblast",
  muscle_exec = "~/bin/muscle3.8.31_i86linux64",
  nproc = 8,
  umi_support = TRUE,
  umi_field = "umi",
  umi_identity = 0.95,
  min_umi_support = 2,
  consensus_copy_fields = "C_CALL",
  consensus_copy_action = "majority",
  filter_args = list(
    locus_val = "IGH",
    min_v_length = 100,
    min_j_length = 10,
    productive_only = FALSE,
    complete_vdj = FALSE,
    min_consensus_count = NULL,
    spatial_id = "barcode",
    add_spatial_sequence_id = FALSE
  )
)

result$db_pass_umi

With umi_support = TRUE, the result has two AIRR tables. db_pass holds every consensus sequence. db_pass_umi holds the sequences with at least min_umi_support reads. You can change the threshold later without running the pipeline again.

Keep the constant region

The consensus covers the V(D)J region only, so the second IgBLAST pass cannot call the constant region. To keep the isotype, put the read-level c_call into the FASTA header. Then give consensus_copy_fields = "C_CALL" and consensus_copy_action = "majority". Each consensus sequence gets the constant region of most of its reads, in c_call, and the fraction of reads that agree, in c_call_freq.

Many samples

processSpatialSamples() runs processSpatialSample() on each input, with the same settings:

processSpatialSamples(
  inputs = c("prepared/slice1.fasta", "prepared/slice2.fasta"),
  output_dirs = c("processed/slice1", "processed/slice2"),
  receptor = "ig",
  igblast_base = "~/share/igblast",
  igblast_refs = "~/share/igblast_refs",
  imgt_dir = "~/share/imgt",
  nproc = 8
)

On a cluster, submit one job per sample and chain instead. Each job then calls processSpatialSample() once.

Choose the parameters

Two parameters have the largest effect on the result:

  • identity is the similarity that two reads need to go into the same cluster in a spot.
  • consensus_freq is the fraction of reads that must agree at a position. If fewer reads agree, the consensus gets an N at that position.

A standard Visium spot is 55 µm wide and holds many cells. Two BCRs in the same spot that differ by one base can come from two related B cells after somatic hypermutation. For BCRs, use identity = 1.0, so that SIRUP does not merge them. TCRs do not mutate, so a one-base difference in a spot is more likely a sequencing error. For TCRs, use identity = 0.99. In the SIRUP paper, consensus_freq = 0.51 gave the most high-quality sequences for both chains.

To compare settings, run processSpatialSample() with each value. Clustering and alignment depend on identity only, so with skip_existing = TRUE you can try several consensus_freq values and reuse the clustering.

Filter the consensus table

The pipeline writes the consensus sequence_id as <cluster>,<barcode>. The example data include the consensus table of MG thymus section 2. It is the db_pass_umi table that processSpatialSample() wrote for the SIRUP paper:

consensus <- airr::read_rearrangement(
  file.path(extdata, "mg_thymus_slice2_bcr.tsv.gz")
)
head(consensus$sequence_id)

#> [4] "6,TGATTCCCGGTTACCT"  "5,CCTACATTCACAGACG"  "3,CCTACATTCACAGACG"

extractSpatialIds() copies the part of an ID that a regular expression matches into a new column. The suffix argument adds -1, so the barcode matches the spot names that Space Ranger writes:

consensus <- extractSpatialIds(
  consensus,
  id = "sequence_id",
  spatial_id = "barcode_10x",
  regex = ",([ACGT]{16})$",
  suffix = "-1"

Then filter. These settings match the definition of a quality sequence that we used to tune the pipeline in the SIRUP paper: a productive rearrangement, a V alignment of at least 250 nucleotides, a J of at least 30, a junction of at least 10, and no gap longer than 15 nucleotides.

bcrs <- filterAirr(
  consensus,
  locus_val = "IGH",
  min_v_length = 250,
  min_j_length = 30,
  min_junction_length = 10,
  productive_only = TRUE,
  min_consensus_count = NULL,
  max_gap_length = 15,
  spatial_id = "barcode_10x"
)
#> filterAirr kept 2078 of 3801 rows (dropped 1723).

nrow(consensus)
#> [1] 3801
nrow(bcrs)
#> [1] 2078

This table is db_pass_umi, so every row already has at least two reads. In UMI mode, consensus_count counts molecules, not reads, so set min_consensus_count = NULL and use min_umi_support for the read floor. Without UMI support, consensus_count counts reads. Then use min_consensus_count = 2.

max_gap_length depends on the locus. IMGT numbering pads TRBV alignments with longer gaps than IGHV alignments, so a limit of 15 removes valid TRB sequences. The SIRUP paper used 15 for IGH and 24 for TRB.

The table is now ready for createSIRUP().

Visium HD

Visium HD reads carry a 2 µm barcode, such as s_002um_00001_00002-1. Most analyses use 8 µm or 16 µm bins. Space Ranger writes a file that maps each 2 µm barcode to its larger bins (barcode_mappings.parquet). readSpatialIdMapping() reads it. Parquet files need the arrow package. You can also save the file as CSV once and read that.

# bcrs$barcode_2um holds the 2 µm barcode of each consensus sequence.
mapping <- readSpatialIdMapping("outs/barcode_mappings.parquet")
mean(bcrs$barcode_2um %in% mapping$square_002um)

bcrs <- bcrs |>
  left_join(
    select(mapping, square_002um, square_008um, square_016um),
    by = c("barcode_2um" = "square_002um")
  ) |>
  rename(barcode_8um = square_008um, barcode_16um = square_016um)

Check the match rate before the join. If few 2 µm barcodes match, compare a few values from each table. The two tables must write the row and column of the bin in the same order (s_002um_<row>_<col>-1).

Load the 8 µm bins with Seurat::Load10X_Spatial(bin.size = 8), and give spatial_id = "barcode_8um" to createSIRUP().

collapseTopConsensusPerSpatialId() keeps the consensus sequence with the most reads in each spatial ID and locus. Use it when you expect one cell for each spatial ID, for example at single-cell resolution.

Identical sequences in neighboring spots

Transcripts can diffuse a short distance before capture. The same molecule can then appear in neighboring spots. On Visium HD, where 2 µm bins sit next to each other, this spatial bleed is common. collapseIdenticalNeighbors() finds groups of neighboring spots that hold the same exact sequence. It keeps one spot per group: the spot with the highest consensus count, or the spot nearest the group center if there is a tie.

The function also merges rows with the same sequence in the same spot and adds their counts. It keeps rows whose spot is not in the Seurat object, such as bulk rows, without changes.

Use it on Visium HD data only. Standard Visium spots are 55 µm wide, 100 µm apart, and hold several cells each. Two neighboring Visium spots with the same sequence are more likely two related cells than spatial bleed.

The function estimates the neighbor distance from the spot coordinates. Set num_neighbors_non_boundary to the number of neighbors that a spot in the middle of the tissue has: 6 on the standard Visium hexagonal grid, 8 on the Visium HD square grid. The example below runs it on the Visium thymus data only to show the call and the output:

thymus <- readRDS(file.path(extdata, "mg_thymus_slice2_spatial.rds"))
sirup <- createSIRUP(
  spatial = thymus,
  receptors = bcrs,
  spatial_id = "barcode_10x",
  image_scale = "lowres",
  swap_coords = FALSE
)

collapsed <- collapseIdenticalNeighbors(
  sirup,
  sequence = "sequence_alignment",
  num_neighbors_non_boundary = 6
)
