Custom read layouts and whitelists

Custom read layouts and whitelists are configured in the standalone rrad package, before SIRUP processing. SIRUP consumes the resulting annotated FASTA; it does not register layouts, manage RAD binaries, or perform demultiplexing.

Install rrad separately using the preparation guide. These examples are not evaluated during rendering and require reads that match your chosen assay.

Describe the read structure

A layout CSV contains one ordered row per sequence element. Static elements provide known anchors; variable elements describe the barcode, UMI, or biological read extracted between those anchors.

Column Meaning
id Unique element name.
seq Sequence for a static element; blank for a variable element.
expected_length Length of a fixed-width variable element, such as a barcode or UMI; leave an unconstrained read blank.
type static or variable.
class Extraction role such as barcode, umi, or read, or an anchor class such as linker.
whitelist Barcode kit key or local whitelist path for a barcode element; otherwise blank.

This illustrative structure is primer, 16-base barcode, 10-base UMI, biological read, reverse primer. Replace the sequences and lengths with those for your experiment.

dir.create("prepared", recursive = TRUE, showWarnings = FALSE)
layout <- data.frame(
  id = c("primer", "barcode", "umi", "read", "reverse_primer"),
  seq = c("CTACACGACGCTCTTCCGATCT", "", "", "",
          "GTACTCTGCGTTGATACCACTGCTT"),
  expected_length = c("", "16", "10", "", ""),
  type = c("static", "variable", "variable", "variable", "static"),
  class = c("linker", "barcode", "umi", "read", "linker"),
  whitelist = c("", "10x_5v1", "", "", ""),
  stringsAsFactors = FALSE
)
layout_path <- "prepared/custom-layout.csv"
write.csv(layout, layout_path, row.names = FALSE, quote = FALSE)

Pass the file path directly to rrad. No SIRUP registration step is needed. rrad also accepts supported seqspec YAML layouts; explicit local onlist paths can supply custom barcodes. Consult ?rrad::rad_demux and the RAD layout reference for orientation, compound barcodes, and the full layout schema.

Check a pilot demultiplexing run

pilot <- rrad::rad_demux(
  layout = layout_path,
  fastq = "my_reads.fq.gz",
  out_dir = "prepared/pilot",
  output = "sample",
  max_reads = 10000,
  write_debug = TRUE
)

pilot$artifacts$layout
pilot$artifacts$position_map
pilot$stats
pilot$log

rrad prepares the layout and position map within demultiplexing. Inspect these artifacts and the passing reads against the expected structure, then adjust the layout if needed. The max_reads limit controls demultiplexing; the internal position-map calibration can sample up to 50,000 input reads. Use a small input file when bounding all pilot work is important.

Supply a whitelist

A layout can reference a built-in kit or a local whitelist. At the run level, kit and global_whitelist are alternatives; custom_whitelist supplies the trusted/sample barcode set. auto_whitelist = TRUE discovers that set automatically and is an alternative to custom_whitelist.

To scan separately around an assay-specific anchor:

scan <- rrad::rad_scan_wl(
  input = "my_reads.fq.gz",
  adapter_seq = "CTACACGACGCTCTTCCGATCT",
  barcode_length = 16,
  output_prefix = "prepared/discovered"
)

scan$artifacts$whitelist

Inspect the scan results before using the selected barcode set. For paired barcodes, rrad::rad_scan_wl() supports bc1_whitelist and bc2_whitelist together, with the extraction lengths and offsets configured for the assay. Large built-in resources are downloaded by rrad on first use and cached; custom local files are used directly.

demux <- rrad::rad_demux(
  layout = layout_path,
  fastq = "my_reads.fq.gz",
  custom_whitelist = scan$artifacts$whitelist,
  out_dir = "prepared/full",
  output = "sample"
)

Omit custom_whitelist to use only the whitelist configured in your layout, or replace it with a path to your own trusted barcode file.

Hand the FASTA to SIRUP

prepared <- rrad::rad_reformat(
  demux,
  output_fastq = "prepared/sample-igblast.fasta",
  to_fasta = TRUE,
  header_format = "presto"
)

This writes headers such as read1|BARCODE=BC01|UMI=ACGT. The barcode and UMI remain part of the identifier when the FASTA passes through IgBLAST. Use prepared$artifacts$fasta as input to SIRUP::processSpatialSample() with the IgBLAST installation, database, and germline paths shown in the preparation guide. Ordinary FASTA input receives the first IgBLAST pass before filtering and consensus; input_type = "spatial_fasta" is reserved for already annotated and filtered consensus input.
